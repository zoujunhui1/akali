# 技术方案

## 技术栈
Kotlin + Jetpack Compose，单模块；Media3 ExoPlayer + MediaSessionService；OkHttp 下载 + Jsoup 解析；Room；MVVM；Navigation Compose；不用 Hilt（手写简单容器）。

## 分层
```
UI (Compose) → ViewModel → Repository → 数据源 (Room / 文件 / 网络)
```
类比 React：Compose 是组件，ViewModel 像 store / 自定义 hook，Repository 像 API 层。

## 页面
课程列表（含排序、多选清除）、播放页（文稿显示/隐藏、模式、调速）、设置页（存储占用、电池/通知引导、导入）。

## 数据模型（Room）
Lesson：
- `id`
- `level`（B2 / C1）、`number`（int）：排序用，不要用字符串排序
- `title`
- `sourceUrl`（可空：导入的课程若没有 url.txt 则为空）
- `addedAt`
- `audioDownloaded`（bool）
- 文稿：文件 `transcript.txt`，或直接存列（几 KB，两种都行，实现时定）

文件位置：`filesDir/lessons/<id>/audio.mp3`、`transcript.txt`。

## 解析 ELLLO（已废弃：app 不再抓取，改由 `mac/elllo_fetch.py` 抓，规则相同，见 架构方案.md）
已用 C1-033 页面实测（`https://elllo.org/video/C1ADV/C1-033-Saif-Social-Media.htm`）：
- 页面里有 9 个 mp3：8 个单词小音频（`../../ANA/...`）+ 1 个主音频。**取 `/Audio/` 目录下的那个**，如 `../../Audio/1ME-C1ADV/C1-033-Saif-Social-Media.mp3`，相对路径要按页面 URL 解析成绝对地址。实测返回 200，约 0.65 MB。
- 文稿：`div#transcript` 下所有 `<p>` 的文字，段落间空行；`span.audionotes` 是生词标注，只取文字。
- 课程 URL 规律：`https://elllo.org/video/<B2INT|C1ADV>/<编号>-<人名>-<主题>.htm`。
- 标题：从页面 `<title>` 或 URL slug 取；level、number 从 slug 取（`B2-036`）。
- 页面还有 Vimeo 视频和测验，不需要。
- 解析失败必须给出明确提示（找不到音频 / 找不到文稿），不要静默失败。
- 用保存下来的几份 HTML 写单元测试，ELLLO 改版时能第一时间发现。
- 使用时注意：自用下载，不要高频请求。

## 下载（已改：音频从后端下载并校验，见“第 4 步”；下面是旧的 ELLLO 下载设计，仅作参考）
- 一课约 1.3 MB，用协程 + OkHttp 流式写入**临时文件，完成后再改名**，避免留下半截文件。
- 暂不引入 WorkManager；以后批量下载再换。

## 导入已有 68 课（已废弃：已由 `mac/upload_existing.py` 批量传到后端，app 里的文件夹导入已删除）
- 系统文件夹选择器（SAF）选一次 `elllo/`，用 DocumentFile 遍历，复制进私有目录。
- 文件夹内取**第一个 `.mp3`** 和 `transcript.txt`，不依赖文件名；有 `url.txt` 就读进 `sourceUrl`。
- 忽略 mp4 / srt / vtt。
- 一次性脚本给每个文件夹补 `url.txt`：以课程编号为键，从 ELLLO 的级别目录页（`/video/B2INT/index.htm`、`/video/C1ADV/index.htm`）取真实链接，再请求验证；不要用现有文件夹名直接拼链接（大小写不统一，有拼写差异，如 Tatoo / Atrology）。

## 播放（Media3）
- `MediaSessionService` 持有 ExoPlayer，UI 通过 `MediaController` 连接。服务独立于页面生命周期，类似放在组件树外的全局 store；退出界面音乐继续。
- 队列 = 当前列表里**已下载**的课，按当前排序，从点击的那课开始；未下载的跳过。
- 播放模式对应：单课循环 `REPEAT_MODE_ONE`；列表循环 `REPEAT_MODE_ALL`；顺序 `REPEAT_MODE_OFF`；随机 `shuffleModeEnabled`。
- 调速：`setPlaybackParameters`（0.75x / 1x）。
- 课间停顿 2 秒：`setPauseAtEndOfMediaItems(true)`，在 `onPlayWhenReadyChanged(false, END_OF_MEDIA_ITEM)` 且“单课循环或还有下一课”时，延迟 2 秒再 `play()`；用户操作会取消等待。**已在模拟器验证**：列表循环、单课循环每遍之间都停约 2 秒；顺序播放到最后一课停止。
- 前台服务 + 媒体通知；Android 13+ 申请 `POST_NOTIFICATIONS`。
- 一加后台保活：设置页引导用户把本 app 电池设为“不受限制”。

## 排序
在 ViewModel 里对 Room 的课程列表做内存排序（`List<Lesson>.sortedFor(SortOrder)`，几百课没有性能问题，且有单元测试）。连播顺序跟随当前排序。

## 构建与运行（全部命令行，用户不用 Android Studio）
- 三个部分在仓库里分开：`android/`（app）、`server/`（后端）、`mac/`（Mac 工具）。
- JAVA_HOME 用 Android Studio 自带的 JBR 21：`/Applications/Android Studio.app/Contents/jbr/Contents/Home`（系统 JDK 26 太新，AGP 不认）。
- Gradle 9.5.0（wrapper）、AGP 9.3.3、Kotlin 2.4.21、KSP 2.3.12；compileSdk 37、targetSdk 36、minSdk 30。Android SDK 在 `~/Library/Android/sdk`。
- app 构建（在 `android/` 目录）：`JAVA_HOME=… ./gradlew assembleDebug`，APK 在 `android/app/build/outputs/apk/debug/app-debug.apk`。服务器地址和 app 口令来自 `android/local.properties`（`akali.server`、`akali.appToken`，不进 git）。
- 单元测试：`./gradlew testDebugUnitTest`；设备测试：`ANDROID_SERIAL=emulator-5554 ./gradlew connectedDebugAndroidTest`（**会卸载 app 并清数据，手机和模拟器同时连着时必须指定 emulator-5554，绝不能在真机上跑**）。
- 后端：`cd server && set -a; . ./.env; set +a; go test ./...`（需要本机 MySQL 的 `akali_test` 库），部署 `server/deploy.sh`。
- Mac 工具：`mac/start.sh`（akali studio，`http://127.0.0.1:18765`）。
- 模拟器：AVD `Pixel_8`（API 37），`emulator -avd Pixel_8 -no-audio`；用 `adb exec-out screencap -p` 截屏自查；`adb dumpsys media_session` 看播放状态。
- 装到真机：USB 或无线调试连上后 `adb -s <序列号> install -r …/app-debug.apk`（覆盖安装，保留数据）。
