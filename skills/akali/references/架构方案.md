# 架构方案（2026-10-24 与用户确认，开发中）

## 目标
app 的数据全部由云上后端提供；所有重活（抓取、语音识别、读飞书）在 Mac 本机完成，结果上传后端；app 同步后本地缓存，离线播放。

## 三个部分（仓库里分开放：`android/`、`server/`、`mac/`）
- **Mac 工具 akali studio**（Python，本机页面 `http://127.0.0.1:18765`，启动 `mac/start.sh`，放仓库 `mac/`）：贴 ELLLO 链接处理新课（抓页面、下音频、提文稿、Whisper 识别）；每课“更新词表”（读飞书、对到文稿）；每课“重新识别”；每课“从服务器删除”（只删服务器，本地文件夹保留）；课程列表显示音频/时间戳/词表/是否已上传的状态；通过管理接口上传。现有 `mac/gen_timestamps.py`、`mac/export_vocab.py` 复用。
- **后端**（Go + Gin + MySQL，放仓库 `server/`；app 读取时带 `created_at`，“最近添加”排序用它）：存数据，给 app 提供接口。
- **app**（`android/`）：只从后端同步，Room 作为本地缓存；不再有“贴链接添加”“选文件夹导入”（同步稳定后删除）。

## 后端
- 部署：Google Cloud VM `coolify-vm`（us-central1-a，Ubuntu 24.04，2 核 3.8GB，无显卡），静态 IP `akali-ip`；机器地址、域名和 SSH 用户名在本机 `server/deploy.env`（不进 git，公开仓库里不写这些）（密钥 `~/.ssh/id_rsa`）。机器上 20201/20202 端口是别的程序，不要动。
- MySQL 直接装系统里（apt，8.0），不用 docker；只监听本机；每天备份。Go 后端编译成单个程序，systemd 运行。本地开发用 Mac 上的 MySQL，新建 `akali_dev` 库，不碰 arbitrage / parks_explorer / trustchain。
- https：Caddy + `<IP 用连字符>.sslip.io` 自动证书（具体域名见 `server/deploy.env`），对外只开 80、443（需在 GCP 防火墙放行，动手前先问用户）。
- 表：课程（编号、标题、来源链接、文稿、音频位置和大小、时间戳 JSON、词表 JSON、更新时间、递增版本号）；时间戳/词表直接存 app 现在读的 JSON；音频文件放硬盘 `/var/lib/akali/audio/`。
- app 接口（口令 A）：取课程列表（只返回上次同步后有变化的）、取某课文稿/时间戳/词表、取某课音频（支持 Range）。
- 管理接口（口令 B，和 A 不同）：新建/更新课程、上传音频、时间戳、词表、删除。
- 词表只存最新状态；学习记录以后再做。

## app 同步规则
- 同步（设置页按钮 + 打开 app 时）只拉文字类数据；**音频不自动下载，点哪课下哪课**，沿用现有的“清除音频/重新下载”流程，下载源改为后端。
- 服务器地址和口令 A 构建时写进安装包，不进 git。

## 顺序
1. 后端（本地 MySQL，接口+测试）。2. Mac 批量上传现有 69 课（先本地后端）。3. 部署到云，再传一次。4. app 改成同步。5. Mac 页面。6. 清理旧添加/导入。
