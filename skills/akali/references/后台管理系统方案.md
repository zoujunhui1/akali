# 后台管理系统方案（2026-10-26 讨论稿，还没开工）

## 目标
把现在跑在 Mac 上的“做内容”的工作（听力课处理、文章导入、字典制作、牛津词典构建）全部搬到云服务器上，做成一个要登录的后台管理系统。Mac 只当浏览器用，手机用的服务（第一台）保持干净。

## 已定的决定（都是用户定的）
1. **两台云机器分工**：第一台只服务手机；第二台是后台管理机，放管理系统、重活脚本和所有素材原件。
2. **技术**：后端 Go + gin，前端 React；要登录；放在现有仓库里，但是**新建单独的目录**。
3. **两个数据库**：第一台 MySQL（给手机，现有）；第二台另装一个 MySQL（给后台管理系统，库名 `akali_admin`）。两个库之间**不直连**。
4. **两台之间只通过第一台已有的 `/admin` 接口交换内容**（和现在 Mac 上传的方式一样），第二台从不直接写第一台的数据库；原因：同步靠的版本号由第一台程序在修改时自动加，绕过程序会让手机同步不到。
5. 备份先不管（以后再定）。
6. 重活（Whisper、OCR、发音）放第二台。

## 整体结构
```
手机 ──同步、AI──▶ 第一台：akali-server + MySQL(给手机) + Caddy
                       ▲  上传、读取（/admin 接口，管理口令）
Mac 浏览器 ──https+登录──▶ 第二台：Caddy → 管理后端(Go+gin) ─ 任务队列 ─ Python 重活脚本
                                       │                     └ 素材原件（磁盘）
                                       └ MySQL(akali_admin，给管理系统)
```
- 第二台的 Caddy 提供 React 网页，并把 `/api` 转发给本机的管理后端；对浏览器是同一个地址，登录 cookie 不会有跨域问题。
- 管理后端只监听本机，不对公网开放，外面只能通过 Caddy 进来。

## 仓库目录（草案）
```
admin-server/        管理后端，Go 模块，单独编译成 akali-admin（只在第二台跑）
  cmd/akali-admin/   入口
  internal/
    auth/            登录、会话、登录失败锁定
    jobs/            任务队列（存盘、一次只跑一个重任务、取消、日志）
    akali/           调用第一台 /admin 和 /api 的客户端（对应现在的 akali_client.py）
    （每个模块是 Go 里的薄薄一层：接收页面请求、建任务、调用对应的 Python 脚本、记日志）
    listening/       听力课
    reading/         文章导入
    dict/            字典制作
    vocab/           牛津词汇主题
    store/           第二台 MySQL 的读写
  migrations/        表结构变更（SQL 文件，按顺序，启动时自动执行）
admin-web/           React（Vite + TypeScript）
tools/               Python 重活脚本（Whisper、OCR、Kokoro、PDF 文字），由 Go 当子进程调用
server/              第一台后端（现有，只加只读管理接口）
```
- 管理后端独立成模块，不和第一台 akali-server 混在一起（登录页的风险不会连累手机服务）。
- **用户明确：Go 只用于后台管理系统本身，所有处理脚本继续用 Python**（抓网页、Whisper、OCR、发音、字典制作、上传校对都是 Python）。`tools/` 就是现在 `mac/` 里那些脚本搬过来，不改写成 Go；Go 只负责登录、任务队列、页面接口和调用脚本。

## 第二台的数据库（akali_admin，草案）
- `admin_user`：用户名、密码哈希（只有一个人用）。
- `sessions`：会话编号（只存哈希）、过期时间、来源 IP。
- `login_attempts`：失败次数和锁定截止时间。
- `jobs`：编号、类型、标题、参数（JSON）、状态（排队/运行/成功/失败/中断/已取消）、开始和结束时间、错误原因。
- `job_logs`：任务编号、时间、一行日志。
- `materials`：素材清单（听力课、牛津主题等，本机路径、状态、最后一次上传时间、校验值）。
- `settings`：键值设置。
- 表结构用迁移文件管理，放仓库，程序启动时自动执行；库每日备份先不做。

## 管理后端接口（草案）
- 登录：`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`。
- 任务：`GET /api/jobs`、`GET /api/jobs/:id`（含日志）、`POST /api/jobs/:id/cancel`。
- 听力：`GET /api/lessons`、`POST /api/lessons/process`（贴网址）、`POST /api/lessons/:code/redo|upload`、`DELETE /api/lessons/:code`。
- 文章：`GET /api/articles`、`POST /api/articles/preview|upload`、`DELETE /api/articles/:code`。
- 牛津词汇：`GET /api/vocab`、`POST /api/vocab/:code/build|upload`、词条修正。
- 字典：`POST /api/dict/build|upload`。
- 状态：`GET /api/status`（第一台是否在线、各类内容条数、AI 今天用了几次）。
- 除登录外，所有接口都要有效会话；写操作用 POST/DELETE，并检查来源（防跨站请求）。

## 页面（草案）
1. 登录页。
2. 听力课：列表、处理（贴网址）、重做、重新上传、删除。
3. 文章：导入（网址/PDF/EPUB/文字）→ 预览（标题可改）→ 上传；列表、删除。
4. 牛津词汇：主题状态、重新构建、修个别词条。
5. 字典：重新构建、上传。
6. 任务：正在跑的、历史、失败原因、日志。
7. 服务器状态。

## 任务队列（关键）
- 所有处理都变成任务，**记录存盘**，重启后还能看到历史和失败原因；上次没跑完的标记为“中断”。
- 重任务（Whisper、OCR、发音）**一次只跑一个**，免得把内存吃光；轻任务（抓网页、上传）可以并行。
- 用子进程调用 Python 脚本，实时收集输出写进日志；支持取消。
- 管理后端作为系统服务运行，开机自启，崩了自动重启。

## 登录和安全
- 单人账号，用户名 + 密码，**密码只存哈希**（bcrypt 一类）。
- 登录后发会话 cookie（HttpOnly、Secure、有过期时间），退出即失效。
- 连续输错会锁一段时间，防暴力猜。
- 全程 https（第二台的 Caddy 自动申请证书）。
- 密码由用户自己设置：本机脚本里输入，只把哈希写到服务器；**密码和口令都不经过 AI、不进仓库、不贴到聊天里**。
- 管理口令（调用第一台 `/admin` 用的）只放第二台的环境文件里，不放前端。

## 第一台要改的
- 加一两个**只读**管理接口（如 `/admin/stats`：各类内容条数、AI 今天用量），其余不动。

## 第二台要准备的
- 装 Python、ffmpeg、poppler、MySQL、Caddy，开 80/443（机器防火墙我来；Oracle 控制台的安全列表要用户自己点）。
- 地址先用 IP 域名（sslip）。
