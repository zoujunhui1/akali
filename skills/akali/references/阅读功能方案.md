# 阅读功能方案（2026-10-25 定稿并做完，已部署、已装手机）

## 目标
自己用的阅读功能：导入英文文章（网页链接、新闻、PDF、EPUB、粘贴的文字），读的时候点词、点句看讲解，把生词收进生词本，用“挖空原句”的卡片复习。用户读到的词汇和句子会有很多不懂的，所以要做到：查词快、不依赖网络、不乱花 AI 用量。

## 总体流程
Mac 的 akali studio 导入 → 转成“干净文章” → 上传服务器 → 手机同步 → 阅读页读 → 生词本复习

## 已定的决定
1. **手机上只认一种格式：干净文章**（标题、来源、段落、句子，存 JSON）。手机用 Compose 原生文字渲染，不用 WebView，这样每个词、每个句子都能点、能高亮、能朗读。
2. **导入放在 Mac 上**（akali studio 页面加“阅读”区），重活（抓网页、转 PDF、识别扫描件、切句）都在电脑上做，结果上传服务器，手机像同步课程一样同步。手机上第一版**不做**粘贴链接和浏览器“分享到 akali”（以后可加）。
3. **点词分层查，省 AI 用量**：先查**手机本地字典**（原形、音标、词性、中文意思、常用程度；免费、秒出、离线）；只有点“结合这句话讲”才请求 AI。点句子（翻译、语法拆解、换个简单说法）也是点了才请求 AI。不会自动批量翻译整篇。
4. **阅读里 AI 的讲解结果哪里都不存**（服务器和手机都不留），每次点都重新请求；服务器只转发、不记录、不存、不回传上游内容。（词汇主题里已有的释义照旧存服务器，不改。）
5. **AI 每天上限从 200 次调到 1000 次**（用户定：自己用不该卡得太紧，但保留“保险丝”防口令泄露或 bug 循环）。**待办**：只改后端一个数字、跑后端测试、部署；用户还没说什么时候改。
6. **生词本**：词、结合的那一句、所在文章、状态（学习中/已会），同步到服务器（防止换手机或重装丢失；如果用户想只放手机，再改）。
7. 隐私：文章内容和词典内容一样，只放用户私有服务器和手机，不进公开仓库；仓库里的测试只用编造的文章。

## 手机上的页面（新增第四个页签“阅读”）
- **阅读列表**：标题、来源、预计阅读时间、读到哪；右上角“生词本”入口。
- **文章页**：大字号、行距宽、字号可调、深浅色跟随系统、记住读到哪；顶栏可开关每段的中文翻译；可朗读句子或整段（可调速）。点词 → 字典卡片（原形、音标、词性、中文意思、常用程度，按钮：加入生词本、结合这句话讲、喇叭发音）；点句子（或长按）→ 翻译、语法拆解、简单英文换说法，可标“难句”。
- **生词本**：每个词带原句；**卡片复习**把原句里的生词挖空，用户先想词，点“显示答案”，认识了就标已会，还不会就留着。和词汇页的图片卡片是同一套玩法，只是“图”换成了“句子”。

## 干净文章的格式（草案）
文章 = 标题 + 来源 + 段落列表；段落 = 句子列表；句子 = 文字（词的切分在手机端按空格和标点做，点击位置由文字布局给出）。长文章（比如一本书）按章节切成多篇，每篇在列表里单独显示。服务器新增文章表，带递增版本号，和课程、词汇主题一起同步。

## Mac 端导入
- 网页链接：抓页面，用正文提取去广告、导航、评论。
- 文字版 PDF：`pdftotext`，再清洗页眉页脚、断行、连字符；扫描版 PDF：先用 Mac 自带文字识别。
- EPUB：拆章节；粘贴的文字：直接切段切句。
- 切句：规则 + 缩写表（Mr.、U.S. 等不当句号）。

## 字典（待核实）
- 想用开源英汉词典数据（候选：ECDICT，带中文释义、音标、词频、考试标签），裁剪成常用几万词的手机内数据库，约十几 MB，离线可查。
- **采用之前必须先核实**：许可证是否允许、内容质量、是否有英美两种音标、怎么做词形还原（running → run）。核实完再给用户确认。
- 字典做好后，可顺带解决“词汇释义里加英美音标”（之前暂缓）。

## 做的顺序
1. 核实并做字典（手机内数据库 + 查词卡片）
2. 点词、点句（AI 请求不存结果）
3. 生词本和挖空卡片复习
4. Mac 页面导入（链接、文字、PDF、EPUB）
5. 导入读了再看要不要加手机端粘贴链接、浏览器分享

## 第一版不做
手机上粘贴链接或浏览器分享、整篇一键翻译、按难度推荐文章、阅读生词和词典图片词汇合并成一个复习队列、AI 流式输出。

## 还没定的小点（推荐做法）

- 生词本卡片答案显示什么？推荐：原词 + 中文意思。
- 长文章怎么切？推荐：按章节切成多篇。
- 生词本是否只放手机？默认同步服务器，用户想改再说。

## 实现情况（2026-10-25）
- **字典**：`mac/dict_build.py` 把 ECDICT（MIT 许可，LICENSE 已核实；原始数据放 `~/Documents/english study/阅读/ecdict/`，不进仓库）裁成常用 5.8 万词 + 3.9 万词形映射，SQLite 约 12.6 MB（中文释义、英文释义、词形变化、音标、考试标签），`--upload` 传服务器；app 在“我的”页下载（有“重新下载”），之后离线查词（原形还原）。ECDICT 的音标是单一一种，没有英美之分；没有例句。旧版字典文件（没有英文释义、词形两列）app 也能读，只是少这两项。
- **导入**：`mac/reading_import.py url|file|text`，网页用 trafilatura 提正文并去掉 `[7]` 这类脚注，PDF 用 pdftotext 清洗（页眉页脚、断行、连字符、跨页段落），EPUB 按章节拆，文字按段和句切分（缩写表防止 Mr.、U.S. 误切）；开头的一两行短行（无句末标点）当标题；`--code R0007` 可重传覆盖；`--dry-run` 只看不传。扫描版 PDF 暂不支持。靠脚本在浏览器里生成正文的网页（如游戏官网的故事页）抓不到，要把正文复制出来用文字导入。
- **akali studio**：页面里有“添加阅读文章”（贴网址、选 PDF/EPUB/txt 文件、贴文字 → 预览，标题可改 → 上传）和“服务器上的文章”列表（可删除）。
- **后端**：表 `articles`、`notebook`；接口 `GET /api/v1/articles`、`GET/PUT /api/v1/notebook`、`GET /api/v1/dict`、`/dict/file`、`POST /api/v1/read/word|sentence|translate`（AI，不存；一次最多 1500 字符）；管理接口 `PUT/DELETE /admin/articles/:code`、`PUT /admin/dict`；AI 每天上限默认 1000。
- **app 交互**（2026-10-25 改定）：底部第四个页签“阅读”。文章用只读输入框显示，**长按选中**一个词或**拖动选一段**，弹出菜单（只留“复制”和我们的几项）：单个词有“查词 / AI讲解 / ♡（收藏，已收藏显示 ♥）”，一段话有“AI讲解”（底部大面板，翻译 + 语法 + 简单说法，一次最多 1200 字符）。**点一下单词没有反应**。“查词”和“AI讲解”在词旁边弹出**小卡片**：词和爱心、音标和喇叭、词性彩色小块 + 中文意思、英文释义、词形变化、考试标签，右下角 AI 按钮（结合这句话讲），讲完有“讲整句”。段落右侧“译”按钮翻译这一段（只放内存）。
- **收藏**：只有“收藏 = 不会”一个概念；收藏的词在所有文章里是淡黄色底（按字典原形归并，running、ran 也认得），取消收藏（菜单 ♥ 或卡片爱心）后各处颜色一起消失；取消后记录标为已删除并同步。生词本里的“已会”状态只在挖空复习点“认识了”时出现，已会的词不再上色。
- **字体**：文章正文和标题用 Literata（衬线，为长时间阅读设计），词卡里的英文用 Inter，都是 SIL OFL 开源字体，随 app 打包（`android/app/src/main/res/font/`，许可证在 `android/fonts-licenses/`）；中文用系统字体。
- **验证**：后端 Go 测试、Mac 的 Python 测试 35 个、app 单元测试都通过；设备测试 23 个当时在模拟器上通过；在模拟器上用本机后端和假 AI 走通了同步、字典、AI 讲解、挖空复习；后来的长按菜单、小卡片、爱心、字体直接装手机由用户使用验证。已部署后端并上传字典、装到手机。
- **踩过的坑**：这个版本的 Compose 里自定义文字菜单要用 `appendTextContextMenuComponents` / `filterTextContextMenuComponents`，老的 `LocalTextToolbar` 不再起作用；系统浮动菜单一行放不下四个长名字的项，多的会被挤进“⋮”，所以菜单项要短。
- **还没做**：选一大段讲解的新提示词（后端已改，要部署才生效）；词汇释义里加音标；“今天该复习”提醒；语法页签；扫描版 PDF 导入；整本书的章节导入还没在真实 EPUB 上试过。
