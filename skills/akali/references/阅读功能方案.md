# 阅读功能方案（2026-10-25 讨论定稿，**还没开始做**）

## 目标
自己用的阅读功能：导入英文文章（网页链接、新闻、PDF、EPUB、粘贴的文字），读的时候点词、点句看讲解，把生词收进生词本，用“挖空原句”的卡片复习。用户读到的词汇和句子会有很多不懂的，所以要做到：查词快、不依赖网络、不乱花 AI 用量。

## 总体流程
Mac 的 akali studio 导入 → 转成“干净文章” → 上传服务器 → 手机同步 → 阅读页读 → 生词本复习

## 已定的决定
1. **手机上只认一种格式：干净文章**（标题、来源、段落、句子，存 JSON）。手机用 Compose 原生文字渲染，不用 WebView，这样每个词、每个句子都能点、能高亮、能朗读。
2. **导入放在 Mac 上**（akali studio 页面加“阅读”区），重活（抓网页、转 PDF、识别扫描件、切句）都在电脑上做，结果上传服务器，手机像同步课程一样同步。手机上第一版**不做**粘贴链接和浏览器“分享到 akali”（以后可加）。
3. **点词分层查，省 AI 用量**：先查**手机本地字典**（原形、音标、词性、中文意思、常用程度；免费、秒出、离线）；只有点“结合这句话讲”才请求 AI。点句子（翻译、语法拆解、换个简单说法）也是点了才请求 AI。不会自动批量翻译整篇。
4. **阅读里 AI 的讲解结果哪里都不存**（服务器和手机都不留），每次点都重新请求；服务器只转发、不记录、不存、不回传上游内容。（词汇主题里已有的释义照旧存服务器，不改。）
5. **AI 每天上限从 200 次调到 1000 次**（用户定：自己用不该卡得太紧，但保留“保险丝”防口令泄露或 bug 循环）。**待办**：只改后端一个数字、跑后端测试、部署；用户还没说什么时候改。
6. **生词本**：词、结合的那一句、所在文章、状态（学习中/已会），同步到服务器（防止换手机或重装丢失；如果用户想只放手机，再改）。
7. 隐私：文章内容和词典内容一样，只放用户私有服务器和手机，不进公开仓库；仓库里的测试只用编造的文章。

## 手机上的页面（新增第四个页签“阅读”）
- **阅读列表**：标题、来源、预计阅读时间、读到哪；右上角“生词本”入口。
- **文章页**：大字号、行距宽、字号可调、深浅色跟随系统、记住读到哪；顶栏可开关每段的中文翻译；可朗读句子或整段（可调速）。点词 → 字典卡片（原形、音标、词性、中文意思、常用程度，按钮：加入生词本、结合这句话讲、喇叭发音）；点句子（或长按）→ 翻译、语法拆解、简单英文换说法，可标“难句”。
- **生词本**：每个词带原句；**卡片复习**把原句里的生词挖空，用户先想词，点“显示答案”，认识了就标已会，还不会就留着。和词汇页的图片卡片是同一套玩法，只是“图”换成了“句子”。

## 干净文章的格式（草案）
文章 = 标题 + 来源 + 段落列表；段落 = 句子列表；句子 = 文字（词的切分在手机端按空格和标点做，点击位置由文字布局给出）。长文章（比如一本书）按章节切成多篇，每篇在列表里单独显示。服务器新增文章表，带递增版本号，和课程、词汇主题一起同步。

## Mac 端导入
- 网页链接：抓页面，用正文提取去广告、导航、评论。
- 文字版 PDF：`pdftotext`，再清洗页眉页脚、断行、连字符；扫描版 PDF：先用 Mac 自带文字识别。
- EPUB：拆章节；粘贴的文字：直接切段切句。
- 切句：规则 + 缩写表（Mr.、U.S. 等不当句号）。

## 字典（待核实）
- 想用开源英汉词典数据（候选：ECDICT，带中文释义、音标、词频、考试标签），裁剪成常用几万词的手机内数据库，约十几 MB，离线可查。
- **采用之前必须先核实**：许可证是否允许、内容质量、是否有英美两种音标、怎么做词形还原（running → run）。核实完再给用户确认。
- 字典做好后，可顺带解决“词汇释义里加英美音标”（之前暂缓）。

## 做的顺序
1. 核实并做字典（手机内数据库 + 查词卡片）
2. 点词、点句（AI 请求不存结果）
3. 生词本和挖空卡片复习
4. Mac 页面导入（链接、文字、PDF、EPUB）
5. 导入读了再看要不要加手机端粘贴链接、浏览器分享

## 第一版不做
手机上粘贴链接或浏览器分享、整篇一键翻译、按难度推荐文章、阅读生词和词典图片词汇合并成一个复习队列、AI 流式输出。
